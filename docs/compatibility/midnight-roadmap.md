# Midnight roadmap and the pinned target

Checked on 2026-11-19 against Midnight's public roadmap and Ledger 9 release notes. Noctium's development qualification still uses Ledger 9.1.0.1 and ZKIR 3.2.1. Midnight reports Ledger 9 on its public networks and newer 9.1.0.2 client packages as of November 17. The development receipts apply to the pinned localnet. [Midnight roadmap](https://midnight.network/roadmap) · [Ledger 9 release notes](https://docs.midnight.network/relnotes/ledger-9)

| Roadmap item | What the current target supports | Noctium work |
| --- | --- | --- |
| Dynamic code discovery | A call claim binds the target address, entrypoint hash and communication commitment. The address is a runtime value. | The typed registry example already rotates between two independently deployed callees. Generalize route/ABI matching and governance through the composition work. [Native call claims](../development/native-call-claims.md) · [Issue 50](https://github.com/awjreynolds/noctium/issues/50) |
| Verified app-to-app calls | Ledger 9's callee context exposes the parent contract address. The parent claim commits to the callee's entrypoint. The current callee context has no authenticated parent entrypoint field. | Require the parent address today. Qualify function-level caller identity when an upstream mechanism binds the parent's entrypoint to the callee's view. [MPS-0040](https://github.com/midnightntwrk/midnight-improvement-proposals/blob/main/mps/mps-0040-cross-contract-call-provenance.md) · [Issue 50](https://github.com/awjreynolds/noctium/issues/50) |
| Private composability (Q1 2027) | Two Noctium witness owners already prove their parts of the same call independently on localnet. Each owner retains its own private state. The exchanged call material and transaction structure are public. | Extend the proven flow to durable private-state recovery and SDKs. Qualify private arguments and return values against the released protocol. [Independent composition](../development/native-call-claims.md#prove-calls-with-separate-witness-owners) · [MPS-0021](https://github.com/midnightntwrk/midnight-improvement-proposals/blob/main/mps/mps-0021-phase2-contract-to-contract.md) |
| Enterprise key support | ZKIR v3 has the curve, hash and arithmetic operations used by Noctium's Ed25519 and P-256 signature helpers. | Extend native signature coverage to enterprise key encoding and representative approval statements. Use the existing helpers. [Signature helpers](../development/signatures.md) · [Issue 75](https://github.com/awjreynolds/noctium/issues/75) · [Issue 76](https://github.com/awjreynolds/noctium/issues/76) |
| Versioned serialization standards | Ledger 9 defines FAB encodings and schema-tagged logs. Noctium separately matches the pinned Compact wire format for selected scalars and aggregates. | Keep the current codecs. Adopt the versioned contract data format when its schema and conformance vectors are published. [Aggregate codecs](../development/aggregate-serialization.md) · [MPS-0042](https://github.com/midnightntwrk/midnight-improvement-proposals/blob/main/mps/mps-0042-serialization-format.md) |
| Directed disclosure (Q1 2027) | A localnet example binds a private value to one recipient's encryption key and publishes ciphertext. | Qualify the shared recipient, key and grant formats once defined. [Directed disclosure example](../development/directed-disclosure.md) · [MPS-0043](https://github.com/midnightntwrk/midnight-improvement-proposals/blob/main/mps/mps-0043-selective-disclosure.md) |
| Private caller verification and proofs in contracts | Noctium's pinned ZKIR inventory defines no proof-verification instruction or recursive-proof input type. Existing native support covers signed statements, witness predicates and public caller-address checks. | Pin the new proof or credential interface once published. Track the privacy statement and authenticated input format before exposing either as a contract primitive. [Pinned ZKIR inventory](zkir-feature-matrix.json) · [Midnight roadmap](https://midnight.network/roadmap) |

The roadmap's offer-file work concerns private trades. Noctium's composition transport already exchanges public call material between independent witness owners. Trade semantics and wallet settlement need separate qualification. [Independent composition](../development/native-call-claims.md) · [Midnight roadmap](https://midnight.network/roadmap)

Proposed MIP-0020 uses an existing native proving primitive to regenerate a prover key from exact ZKIR and the deployed verifier key. No consensus change is required. A Noctium experiment should start on the pinned Rust profile and demonstrate regenerated-key identity and rejection of a mismatched relation before using this in a resolver or SDK. [MIP-0020](https://github.com/midnightntwrk/midnight-improvement-proposals/blob/main/mips/mip-0020-prover-key-regeneration.md)
