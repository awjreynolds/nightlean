# Compiler optimisation strategy

The OpenZeppelin workload took 65.94 seconds before removing the extra frontend pass, 41.29 seconds with one pass, and 38.90 seconds with witness compilation reuse. The artifacts match byte for byte. [Optimization issue](https://github.com/awjreynolds/noctium/issues/85) · [Follow-up measurements](../development/oz-compile-performance.md#single-pass-noctium-follow-up)

When needed, start with one phase profile of the affected compile. Then select the requested artifacts before lowering and remove measured repeated work within one compilation. Repeated range checks on the same immutable operand are a separate circuit candidate. Each change needs a measurable outcome and a small rejection case below.

The original review uses compiler revision `508b85c`. The compiler, typed IR, optimisation passes and lowering belong in Lean. Rust runs the native Midnight libraries. Current scoped support covers all 40 non-deprecated ZKIR v3 opcodes and 15 native type families. [Project scope](../compatibility/GOAL.md) · [Runtime pins](../../runtime/Cargo.toml)

## What the evidence establishes

The published 1,013-line, 16-entrypoint confidential token took **61.811 s** median to compile on an Apple M3 Max with 48 GiB RAM. Compact 0.36.1 `--skip-zk` took **0.255 s**. Each had three fresh processes and warm dependencies. Noctium emitted 16 ledger relations and 13 standalone helper relations. Compact emitted 15 provable relations and a pure JavaScript function. Different ABIs, exports and state handling limit the comparison. Neither command generated keys or proofs. This token declares no contract theorems. [Benchmark and methodology](../development/oz-compile-performance.md) · [Raw samples](../development/oz-compile-performance.json)

The largest measured Noctium entrypoint, `transferFrom`, used **63,125 rows at K16**, against **62,483 rows at K16** for Compact. The published Noctium relation had 1,338 instructions. K20 was outside the experiment. Midnight’s pinned `mock-compile` calls the relation model and reports rows and K. These numbers measure circuit size. Proof time, peak prover memory and native VM gas each need their own observation. The Rust proof path prepares bound calls, and the VM cursor uses the runtime cost model. ## Implementation order

**1. Measure one compile and the work requested.** Use the same source, pinned 3.2.1 profile and a fresh output directory. Time each frontend process. Within them, label source elaboration, source reconstruction and inspection, helper/witness compilation, Impact lowering, ZKIR emission, producer validation, JSON formatting and writing. Record call counts, output roles and bytes. Lean 4.35’s `trace.profiler` records timed trace nodes and supports a Firefox profile. Separate nested time from time spent directly in a phase. Repeat this one profile after each relevant change. The benchmark supplies no phase split or predicted speedup. [CLI](../../Noctium/Cli.lean#L45-L75) · [Pinned profiler options](https://github.com/leanprover/lean4/blob/eb6cafb7290e8bd5f2937522d8d804f58f02bafc/src/Lean/Util/Trace.lean#L175-L199)

**2. Select outputs explicitly.** Repeat `--emit` to select ledger, standalone, witness, control, specialization or observations. The compiler skips unselected exports and retains source validation. The manifest names each emitted file and role. A ledger entry that needs host execution requires the selected witness pair. [Compiler output roles](../development/portable-artifacts.md#select-compiler-outputs)

`--bindings rust` emits per-entrypoint witness modules in `bindings/rust/`. They wrap the existing SDK and require the ledger witness pair. The shared Rust SDK and C/C++ ABI remain available to native clients. Further generators are tracked in the optimization backlog. [Generated Rust modules](../development/typed-witnesses.md#generate-a-rust-witness-module) · [Optimization issue](https://github.com/awjreynolds/noctium/issues/85) · [C/C++ ABI](../development/native-client-abi.md)

**3. Reuse one elaboration and its checked source products.** The CLI now runs one Lean process with an invocation-owned staging directory. A successful frontend run publishes the complete bundle. A failed run discards the staging files. [Frontend](../../Noctium/Cli.lean) · [Late-error test](../../tests/cli.sh)

Within the successful process, rebuild registered source roots once and index their checked products. Reuse a witness compilation between standalone and ledger binding when its source, export, specialization and lowering context agree. Keep the standalone relation and ledger relation distinct. Ledger mode authenticates a different transcript and communications commitment. For hosted ledger entries, retain both components of `compileLedger` where callers currently discard the witness and reconstruct it. Share the Impact plan used by export and ZKIR emission. Keep the validator’s expected schedule independently derived from checked source. Passing an emitter-supplied schedule into both sides would weaken the check. Exercise one mismatched binding and compare requested output bytes for this work-only change. [Source reconstruction](../../Noctium/Compiler.lean#L362-L448) · [Witness compiler at review pin](https://github.com/awjreynolds/noctium/blob/508b85c/Noctium/Witness.lean#L124-L185) · [Discarded witness](https://github.com/awjreynolds/noctium/blob/508b85c/Noctium/Witness.lean#L223-L236) · [Emitter](../../Noctium/Backend/Zkir.lean#L1248-L1264) · [Expected statement](../../Noctium/Backend/NativeExpected.lean#L127)

**4. Tune the dominant Lean routine.** Lean already runs simplification, specialization and common subexpression elimination on compiled Lean functions. Its reference counting permits in-place updates to uniquely owned arrays. These improve execution of the compiler itself. The Noctium backend separately chooses Midnight instructions. If lookup dominates, replace the ZKIR association-list cache with a structural-key map, retaining ordered operands, domain, typing and deterministic first-emission order. Iterate instructions in source order. If construction dominates, replace measured `list ++ [item]` accumulators with a reversed list or uniquely threaded array. Inspect `trace.compiler.ir.result` before adding inline/specialize attributes to hot functions. Use the shadowing/CSE case to catch accidental alias reuse. [Lean pass order](https://github.com/leanprover/lean4/blob/eb6cafb7290e8bd5f2937522d8d804f58f02bafc/src/Lean/Compiler/LCNF/Passes.lean#L93-L140) · [Reference counting and IR](https://lean-lang.org/doc/reference/latest/Run-Time-Code/Reference-Counting/) · [Cache keys](../../Noctium/Backend/Zkir.lean#L108-L155) · [CSE fixture](../../tests/ScalarCseParity.lean)

**5. Reduce constraints with a local preservation argument.** First try skipping a later unconditional `constrain_bits` with exactly the same SSA operand and width after the first check. Preserve all operand definitions, the first check and ordered assertions. Show equivalence of satisfying assignments in both directions and preserve preprocessing rejection behavior. Keep independent source-derived range obligations and the existing producer check. Compare instruction count and official `mock-compile` rows/K on one affected relation, and check an out-of-range input still rejects. Identical `impact` instructions at two positions authenticate two events. Preserve both. Keep UInt bounds, cast failure, Boolean representations, hash domains and curve validity explicit. [Range lowering](../../Noctium/Backend/Zkir.lean#L157-L175) · [Producer obligations](../../Noctium/Backend/NativeProducer.lean#L754-L801) · [Upstream instruction semantics](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/ir.rs#L465-L538)

**6. Shrink plans where host measurements justify the change.** Helpers close guards and ledger expressions over accumulated local bindings. Lean source `let` and `select` evaluate eagerly. Removing an apparently unused partial computation risks changing the first failure. Start with compact JSON if printing or I/O dominates. Refresh hashes for the exact new bytes. If tree duplication still dominates, intern identical expression *syntax* in a versioned, bounded table with backward-only references. Evaluate at each original use in its lexical environment and original order. Preserve expansion limits, guard activity, effect boundaries, public reads and provider ordinals. Share immutable syntax across uses without caching secret values or provider responses. Measure parse/preparation time and bytes on one fixture. An inactive guarded provider must still receive zero invocations. Changing VM operations or gas needs separate transcript/state evidence. Binding deduplication additionally needs authenticated resolution to the exact relation before host execution. ## What Lean proves today

Authors already have Lean’s full theorem language, tactics and kernel. For a new contract, write a specification over its actual source semantics, prove the stated behavior and inspect its dependencies. A privacy claim also needs an observer and permitted disclosures. The historical PrivateClaim source and successful-execution privacy results have explicit scopes. Generic scalar soundness and completeness have a recorded source pin. Later constructors already exceed parts of the optional scalar proof model. For example, `ScalarNormalization.number` handles Native, UInt and Bool. `Ty` also includes bytes and curve types. Future passes need preservation of accepted and rejected behavior at the boundary they change. A claim about deployed behavior additionally depends on actual emitted artifacts, native primitive and verifier agreement, and deployment identity.
