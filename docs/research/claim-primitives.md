# Ledger 9 primitives for a private one-time claim

Context pointer: [Research ledger 9 claim primitives](https://github.com/awjreynolds/noctium/issues/11)

Research checked on 2026-11-16 against official Midnight documentation and source at the release pins below. This is source inspection, not a compatibility test.

## Findings

- **Release baseline.** Mainnet, Preview, and Preprod run ledger 9.1.0.1. Its release notes identify build pins `midnight-circuits` 7.3.0, `midnight-zk-stdlib` 2.4.0, and `midnight-zkir` 3.2.0. The ledger release calls these build pins, not QA-verified versions. The source manifests for circuits 7.3.0 and zk-stdlib 2.4.0 are at `midnight-zk` commit [`24a1eb5`](https://github.com/midnightntwrk/midnight-zk/commit/24a1eb5a59824651fd77cab815ba2d385fbca035); ZKIR 3.2.0 source tag resolves to commit [`446c7fe`](https://github.com/midnightntwrk/midnight-zkir/commit/446c7fecc6bd), with [release notes](https://github.com/midnightntwrk/midnight-zkir/blob/zkir-3.2.0/.github/release-notes/zkir-3.2.0.md). The current network and package-version distinction is documented in [Ledger 9.1.0.1 notes](https://docs.midnight.network/relnotes/ledger/ledger-9-1-0-1) and the [network upgrade page](https://docs.midnight.network/relnotes/ledger-9).
- **Hash and field.** The 7.3.0 source exposes `PoseidonChip`, with both circuit `HashInstructions` and CPU `HashCPU` implementations over `PoseidonField`; see [`poseidon/mod.rs` at the pinned release commit](https://github.com/midnightntwrk/midnight-zk/blob/24a1eb5a59824651fd77cab815ba2d385fbca035/circuits/src/hash/poseidon/mod.rs). ZKIR 3.2 names `Native` as the BLS12-381 scalar field and supports typed field values. Poseidon support in source does not prescribe an application's leaf format, domain tags, or public-state encoding. The ZKIR release adds byte conversions and canonical decoding rules in its [release notes](https://github.com/midnightntwrk/midnight-zkir/blob/zkir-3.2.0/.github/release-notes/zkir-3.2.0.md).
- **Merkle path evidence.** The pinned zk-stdlib includes [`hybrid_mt.rs`](https://github.com/midnightntwrk/midnight-zk/blob/24a1eb5a59824651fd77cab815ba2d385fbca035/zk_stdlib/examples/hybrid_mt.rs), an example with a public field root, private leaf and siblings, a binary tree, and a compile-time path array of 63 siblings for a height-64 tree. Each sibling carries a left/right position. It demonstrates a path shape and Poseidon parent hashing, with SHA-256-derived leaf limbs. The file describes itself as a Compact Interface example. It is not a generic fixed-depth Merkle API, a ledger-required tree shape, or evidence that the SHA-256 leaf format should define Noctium semantics.
- **Nullifier state.** Ledger 9 Zswap state stores nullifiers in `HashMap<Nullifier, ()>`. Applying a spend checks that the root is known, rejects an already-present nullifier, then records it; see [`zswap/src/ledger.rs` at ledger tag commit `a2b3012`](https://github.com/midnightntwrk/midnight-ledger/blob/a2b3012/zswap/src/ledger.rs). Its Zswap `Nullifier` wrapper contains a 32-byte `HashOutput` and has a Zswap-specific serialization tag in [`coin-structure/src/coin.rs`](https://github.com/midnightntwrk/midnight-ledger/blob/a2b3012/coin-structure/src/coin.rs). This establishes Zswap double-spend semantics, not a built-in claim nullifier API. The ledger 9 Impact state model has `Map` and `BoundedMerkleTree` values, with bounded tree heights 1 through 32, in [`onchain-state/src/state.rs`](https://github.com/midnightntwrk/midnight-ledger/blob/a2b3012/onchain-state/src/state.rs). This is a runtime state representation, not a claim-level set contract.
- **Encoding boundary.** ZKIR v3 distinguishes `Native` from bytes and other fields. `BytesIntoNatives` packs 31-byte chunks, which the release notes call a temporary bridge for Compact. Do not adopt that as Noctium's field or hash semantics. The reviewed sources do not establish a canonical JSON/JavaScript encoding for a Noctium public `Native` root or nullifier, nor a stable adapter mapping from these public inputs to persistent contract-map keys. Require explicit canonical input/output vectors in the backend adapter before freezing an external format.

## Recommendation

Bound v1 to a binary membership claim with a public `Native` root and private `Native` secret, fixed-depth sibling array, and private direction bits. Define the leaf and nullifier as separate Poseidon computations with distinct compile-time field domain tags. Expose the nullifier publicly and persist it in contract state; reject the transition when the nullifier already exists, then insert it atomically with claim success. Specify path depth as a compiler profile parameter, not a ledger constant. Treat the exact domain-tag values, Poseidon input layout, external field encoding, and state-map adapter as versioned Noctium choices with conformance vectors. This recommendation is an inference from the available Poseidon, ZKIR, and state primitives, not a Midnight protocol requirement.

## Unverified

- No reviewed source offers a reusable fixed-depth membership-proof API for this claim. The height-64 example is not such an API; the ledger Impact `BoundedMerkleTree` instead caps height at 32.
- No compatibility build or proof test confirmed that Poseidon CPU and circuit outputs, public `Native` inputs, and stored map keys agree across the exact 7.3.0 / 2.4.0 / ZKIR 3.2.0 toolchain.
- Exact field-to-contract and field-to-JavaScript serialization, nullifier domain tags, tree leaf schema, and persistent map update/atomicity behavior for a direct Noctium contract remain unspecified by these sources.
