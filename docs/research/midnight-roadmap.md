# Midnight roadmap and Noctium's next contract capabilities

Checked 19 November 2026. Midnight targets registry discovery and verified app-to-app calls for Q4 2026, and private composability and directed disclosure for Q1 2027. Noctium targets ledger 9.1.0.1 and the ZKIR 3.2.1 source revision in its Rust dependencies. Midnight's public networks run ledger 9.1.0.1, with newer client libraries at 9.1.0.2. Noctium's composed transaction evidence comes from localnet. [Midnight roadmap](https://midnight.network/roadmap) · [Ledger 9 release profile](https://docs.midnight.network/relnotes/ledger-9) · [Noctium pins](../../runtime/Cargo.toml) · [Localnet receipt](../development/native-composition-receipt.json)

## What the pinned versions support

- **Dynamic Code Discovery (Q4 2026). Contract-managed registry proven on localnet.** The claim accepts a runtime address, an entrypoint hash and a communication commitment. Noctium already supports `Bytes32` state reads and dynamic call targets. The roadmap describes registry-based resolution. Compact's 0.36 release notes also document a fix for call targets supplied as arguments. Noctium qualified typed registry calls on localnet. Automatic discovery of the callee's authenticated bundle remains open. Ledger 9 stores optional operation IR and verifier keys. A host still needs a matching execution plan and proving material, a gap described by Midnight's lightweight interaction problem statement. [Claim type at the ledger pin](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/onchain-runtime/src/context.rs#L578-L592) · [Operation storage at the ledger pin](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/onchain-state/src/state.rs#L1130-L1157) · [Noctium byte storage](../development/byte-storage.md) · [Compact 0.36 call fixes](https://docs.midnight.network/relnotes/compact/toolchain-0.36.0#contracts-that-make-cross-contract-calls-must-be-recompiled-and-their-keys-replaced) · [MPS-0039](https://github.com/midnightntwrk/midnight-improvement-proposals/blob/main/mps/mps-0039-lightweight-contract-interaction.md)

- **Verified app-to-app calls (Q4 2026). Immediate caller address supported.** For a matching parent call, the ledger derives `PublicAddress::Contract(caller.address)` and inserts the value before replaying the callee transcript. Noctium exposes `requireContractCaller` for the tagged contract variant in direct entrypoints. The pin uses the parent call's address and drops its entrypoint when constructing the context. Authenticate the parent function through a future upstream context field or a separately specified application protocol. Top-level calls fall back to unshielded input ownership and need separate treatment. [Context derivation at the ledger pin](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/ledger/src/structure.rs#L2922-L2962) · [Transcript replay at the ledger pin](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/ledger/src/semantics.rs#L1443-L1465) · [Compact `kernel.caller()` semantics](https://docs.midnight.network/relnotes/compact/toolchain-0.35.0#the-caller-of-a-circuit-is-available-to-the-circuit)

- **Private composability (Q1 2027). Committed payloads work today.** Noctium assembles one intent with separate proofs whose communication commitments bind the call inputs and outputs. Private payloads stay out of the clear ledger call fields. The calls, entrypoints, claim effects and transaction structure remain visible. The current assembler accepts all prepared executions, including private proof preimages. Separate witness owners need a protocol to agree on the statement, shared payload and opening while each owner keeps unrelated witness data local. Midnight's released design will establish which guarantees count as roadmap equivalence. [Ledger call format at the pin](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/ledger/src/structure.rs#L2889-L2903) · [Noctium assembler](../../runtime/src/assembly.rs) · [Committed values](../development/committed-returns.md) · [Composition proving](../development/native-call-claims.md#prove-a-composed-intent)

- **Directed disclosure (Q1 2027). Recipient-bound example proven on localnet.** Noctium seals a recipient key, binds it to encryption of a private eight-bit value and publishes two ciphertext points. The source theorem identifies the successful call's recipient and observations. The intended key recovered the value from finalized state. A shared `discloseTo` interface depends on Midnight's published format and key model. [Midnight disclosure roadmap](https://midnight.network/roadmap) · [Noctium directed disclosure](../development/directed-disclosure.md)

- **Proof verification inside contracts (Q4 2026). Track an upstream contract interface.** The ledger verifies each call proof against its installed key at the transaction boundary. The pinned ZKIR instruction enum exposes no first-class proof verifier. The Rust proving library already has a gadget for Poseidon-transcript proofs. Its `prepare` method returns an accumulator whose validity still needs checking. The normal ZKIR proving path uses the ledger's Blake2b transcript. A deployable recursive wrapper needs a supported inner proof format, key binding and a way to enforce accumulator validity. [Ledger verification at the pin](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/ledger/src/verify.rs#L2043-L2078) · [Pinned ZKIR instruction set](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/ir.rs#L387-L1270) · [Pinned proving transcript](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/ir.rs#L84-L104) · [Ledger transcript hash](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/transient-crypto/src/proofs.rs#L65) · [Poseidon gadget](https://github.com/midnightntwrk/midnight-zk/blob/5d0eca30a2d67e024672e41978c803482e152e40/zk_stdlib/src/lib.rs#L829-L836) · [Accumulator contract](https://github.com/midnightntwrk/midnight-zk/blob/5d0eca30a2d67e024672e41978c803482e152e40/circuits/src/verifier/verifier_gadget.rs#L683-L714)

- **Serialization standards (Q4 2026). Keep the codecs, await the application format.** Ledger storage already tags native state values and contract state. Noctium declares its layout and encodes its values using native alignment. Compact's typed byte serialization and Noctium's artifact manifest address different formats. Interoperable contract storage needs the published layout, version and decoding rules plus shared fixtures. [Pinned ledger state types](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/onchain-state/src/state.rs#L107-L125) · [Pinned contract-state envelope](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/onchain-state/src/state.rs#L990-L1001) · [Noctium state layout](../development/direct-impact.md) · [Bundle manifest](../development/portable-artifacts.md#canonical-representation-and-limits)

- **Enterprise key support (Q4 2026). Signature primitives already compile.** Noctium's ZKIR 3.2.1 path checks Ed25519 over a bounded raw message and P-256 ECDSA over an explicit 32-byte digest. Native checks cover published vectors and altered messages or digests. A specific passkey or enterprise approval flow still needs to bind the signature to the application action, validate its credential policy and reject replay. [Noctium helpers, protocols and evidence](../development/signatures.md)

## Registry routing on the pinned ledger

Noctium reads a callee address from a caller-owned public registry slot. Lean derives and binds the entrypoint selector from the declared interface. The native material resolver matches the deployed verifier to the selected bundle. Compact 0.36's security fix uses a fixed call-site entrypoint hash. [Compact call-site fix](https://docs.midnight.network/relnotes/compact/toolchain-0.36.0#contracts-that-make-cross-contract-calls-must-be-recompiled-and-their-keys-replaced) · [Noctium typed call boundary](../development/native-call-claims.md) · [Deployed-key check](../../runtime/src/proof/composition.rs)

One localnet run called deployment A, rotated the registry and called deployment B with the same caller and interface. The stale route, a wrong selector and a wrong callee bundle rejected. Hosts supply the operation bundles for the resolver. [Registry routing receipt](../development/native-registry-receipt.json) · [Registry routing ticket](https://github.com/awjreynolds/noctium/issues/86)

## Next work on the current pin

For composition, the next boundary is two independent witness owners. Freeze the call graph and shared commitment before either proof is produced. Check whether each owner can prove its own bound statement and give an assembler only its public projection and proof. This follows from the current proof and commitment format as a design candidate. A localnet run with separate owners is still needed. [Native composition ticket](https://github.com/awjreynolds/noctium/issues/50)
