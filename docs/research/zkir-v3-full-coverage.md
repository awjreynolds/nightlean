# Full native ZKIR v3 coverage and disclosure safety

> Update checked 2026-11-17: This audit records the 2026-11-16 source and disclosure snapshot. The later source snapshot records 18 restricted Native-field producer opcodes and an internal typed Bytes32 hash/encode path, without complete overload, proof, or ledger qualification. Current guarded-effect evidence and remaining limits are summarized in the [source snapshot](../compatibility/zkir-feature-matrix.json) and [OpenZeppelin POC](../development/openzeppelin-port.md).

Research checked on 2026-11-16. Noctium's target is the supported capability set of the pinned native ZKIR v3 implementation together with Midnight ledger composition. Compact feature equivalence is a minimum comparison, not a limit on the source language or backend. The compiler stays in Lean. Compact compiler execution, generated JavaScript and Compact runtime packages are not implementation or required conformance-test dependencies.

The operation/type inventory and its per-entry acceptance requirements live in [zkir-feature-matrix.json](../compatibility/zkir-feature-matrix.json). Source presence, safe Lean source support, official checker acceptance, proof generation and ledger acceptance are separate evidence fields. No inventory entry becomes fully verified merely because one raw ZKIR fixture or one private-claim program succeeds.

## What the input and guard instructions establish

ZKIR is a typed, straight-line relation producer. Its source has separately declared argument types, return types, a communications-commitment flag and an instruction sequence. The implementation contains both preprocessing, which computes the canonical witness and checks transcript consumption, and circuit synthesis, which defines the constraints accepted by a verifier. An off-circuit rejection is not evidence that arbitrary satisfying witnesses face the same restriction in-circuit. [Source container and proof APIs](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/ir.rs#L35), [preprocessing and synthesis](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/ir_vm.rs).

| Instruction or boundary | Actual pinned behavior | Required safe producer rule |
| --- | --- | --- |
| Declared `IrSource.inputs` | Preprocessing decodes exactly the declared typed field widths and rejects an input-count mismatch. Circuit synthesis allocates the corresponding typed witness values | Validate canonical source/ABI values. Do not call an argument public solely because it appears in this header |
| `PublicInput` | Preprocessing consumes the next typed value from public transcript outputs when its optional guard is active, otherwise supplies a typed default. In-circuit, the value is a typed witness and the guard is ignored | Bind its use to the intended ledger read/public statement. Validate guard semantics and transcript order separately |
| `PrivateInput` | Same guarded/default preprocessing pattern, consuming the private transcript. In-circuit, allocation is the same typed-witness mechanism as `PublicInput` | Treat the supplied value as untrusted secret witness data. Enforce all semantic relations and any required inactive defaults through the surrounding constraints |
| `Impact` | Each Native operand contributes `guard ? value : 0` to the proof's public inputs. The guard is converted to an in-circuit bit. Preprocessing produces one activity/skip entry per `Impact` group and consumes public transcript inputs only for active groups | Preserve the exact public-input grouping and skip widths required by the ledger. Reject unauthorized secret-dependent activation and validate the guard as a source Boolean |
| `Encode` | Converts a typed value into its exact Native field representation. The output count must match the type's encoded width | Encoding is representation conversion. Publishing the resulting fields still requires a binding operation and disclosure authorization |
| `ConstrainToBoolean` | Preprocessing accepts zero or one. Synthesis inserts a bit-conversion constraint | Use this or a separately proven Boolean-producing operation for Native values used as source Booleans |
| `Assert` | Preprocessing requires a Boolean value equal to one. Synthesis applies nonzero assertion to a Native value. The enum documents a Boolean precondition | Establish Booleanity before assertion. A preprocessing rejection for input two is insufficient evidence of an in-circuit Boolean assertion |
| `CondSelect` | Resolves both arms and the selector, then selects the result. Synthesis constrains the selector as a bit for supported overloads | Do not use selection as a substitute for guarded witness invocation, lazy source branches, guarded state effects or disclosure analysis |
| `ConstrainEq` and `ConstrainBits` | Add equality/range constraints for supported representations. Preprocessing also checks them | Check exact operand types and legal bit widths before synthesis. A range predicate is not a visibility rule |
| `Output` | Checks the count and exact types against the return signature, and collects encoded return values for communications commitment | Require exactly one final `Output`, coherent return metadata and commitment policy. Do not equate a return with publication in the ledger transcript |

These distinctions come directly from [instruction contracts](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/ir.rs#L396), [guarded transcript preprocessing](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/ir_vm.rs#L423), [guarded public binding](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/ir_vm.rs#L1111) and [input synthesis ignoring guards](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/ir_vm.rs#L1241).

Typed `IrType::Bool` and a Native field element constrained to zero/one are distinct representations. `And`/`Or`/`Xor` require typed Bool operands and return typed Bool values. The control operations above resolve their conditions through Native-field conversion, so a producer needs an explicit representation bridge, such as encoding a typed Bool into its Native field representation, before using it as such a condition. Noctium's currently qualified source Bool values use constrained Native fields. They do not establish tested coverage of the native typed-Bool instruction family. [Typed Boolean and Native resolution](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/ir_vm.rs#L287), [typed representations and conversions](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/ir_types.rs).

Two details require explicit malformed-producer tests. First, `Output` is described as a terminator, but both interpreter loops continue over the instruction list and the `Output` arms append values without a terminating break. Noctium should enforce final-position/single-output well-formedness rather than rely on the description. Second, guarded public/private input reads slice transcript arrays directly before the final full-consumption check. Short or inconsistent typed transcript vectors need deterministic validation at the producer/host boundary. This audit identifies these source behaviors and required tests. It does not claim a deployed exploit. [Preprocessing output and consumption](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/ir_vm.rs#L834), [synthesis output](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/ir_vm.rs#L1568).

## Producer safety is wider than enum membership

The new 3.2.1 type-inference pass chooses required chips, including curve types introduced by intermediate instructions. Its documentation explicitly says the pass is not a type checker. It does not replace producer checks for fresh identifiers, consistent types, complete transcript schemas, canonical encodings, output structure or instruction-specific bounds. The compiler must reject undefined or unsupported combinations before invoking expensive key generation. [Type-inference contract](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/type_inference.rs#L168), [producer-obligation discussion in the older formal model](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir-spec/src/zkir-v3/README.md).

Dispatch implementations narrow several broad enum descriptions. Off-circuit `CondSelect` accepts equal-typed values generally, but the circuit dispatcher has no `Bytes(n)` arm. Off-circuit byte-array equality also compares differing lengths, whereas circuit equality requires equal byte lengths. The frontend should reject unsupported combinations or lower a supported equivalent, with equivalence evidence for the replacement. Accepting a value in preprocessing does not establish a working proving route. [Selection dispatch](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/ir_instructions/select.rs), [equality dispatch](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/ir_instructions/eq.rs).

Alignment-sensitive byte hashing is also narrower than an unrestricted FAB serializer. The pinned in-circuit alignment decoder rejects optional alignment segments as unimplemented and rejects compression atoms. Preprocessing follows the separate `alignment.parse_field_repr` path, so off-circuit acceptance does not establish synthesis support. Each hash/serialization overload therefore needs accepted alignment cases and deterministic rejection cases. Native byte support does not prove arbitrary nested application values hash or serialize correctly. [In-circuit FAB decoding](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/ir_vm.rs#L130), [off-circuit aligned hashing](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/ir_vm.rs#L565).

Canonical type/encoding rules belong in the source ABI and compiler checks. The native implementation bounds `Bytes(n)` to `1..2^24`, packs 31 bytes per Native field element, gives different field widths to different foreign points/scalars, and distinguishes curve identities. A byte buffer, foreign limb vector and Native field vector are not interchangeable merely because all eventually enter a serialized proof preimage. [Type and width definitions](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/ir_types.rs), [typed encoding](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/ir_instructions/encode.rs).

## Mandatory guarded disclosure policy

The following is a required safety contract for the active Noctium goal, not a claim about the present compiler. The current IR records input visibility but has no general expression/effect information-flow analysis. Its ordinary `select` evaluates both arms. The native lowerer binds public values and complete VM opcode fields with unconditional `Impact` guards. That is working subset behavior, not guarded private execution or an enforcement policy for future source constructs. Bounded unsigned-number work visible in the working tree is a separate scalar slice and adds no disclosure guarantee. [Current IR](../../Noctium/IR.lean), [Lean semantics](../../Noctium/Semantics.lean), [ZKIR lowerer](../../Noctium/Backend/Zkir.lean), [native host evaluator](../../scripts/zkir/native-runtime.mjs).

Source typing should track data sensitivity and the sensitivity of the active control path. Public outputs, ledger writes, keys and indices, event payloads, cross-contract call metadata and arguments, token effects, public transcript operands and activity decisions are disclosure sinks. A secret control condition influences a public effect even if its payload is constant. The compiler should reject this flow unless an explicit source disclosure operation authorizes the relevant value or decision, or a checked transformation establishes independence of the observable result. A useful negative case is a private condition choosing whether to write public value one. Removing the secret from the payload does not remove the branch leak. This requirement follows from the ledger's public transcript/effects and guarded-noop mechanism, rather than from a privacy property supplied by the `Impact` opcode. [Guarded binding semantics](https://github.com/midnightntwrk/midnight-zkir/blob/7a51b3385bbf4bce3604df87a7c70867c9ab43c0/zkir/src/ir_vm.rs#L588), [ledger activity rewriting](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/ledger/src/prove.rs#L254).

The policy must distinguish an approved public commitment or nullifier from an arbitrary private value crossing into the transcript. Hashing alone should not remove a sensitivity label. The source disclosure boundary should name the permitted release and retain metadata useful for review. Source-level branch rules must cover witness invocation, assertions, state effects, public activity and errors, including nested branches and indirect helper calls. Public branch decisions should be bound to the intended public statement. Secret branch decisions need either authorized release or an execution strategy whose public observables do not depend on the unreleased decision. Proving correctness of the chosen branch does not prove this noninterference property.

Acceptance should pair executions with the same approved public inputs and disclosures but different secrets. Compare public VM programs, activity/noop structure, effects, events, call identity, output encodings and declared costs. Add compile-time rejection tests for direct and indirect secret-to-public flows, unauthorized guard activation, hidden state indices, witness-derived addresses and nested helper disclosure. An explicitly authorized disclosure should preserve proof binding to the released value. These are compiler and runtime tests still required, not results of this audit.

Private witnesses and private-state execution form another trust boundary. The host must validate witness responses and exact types, define call order and replay behavior, and document when proposed private state becomes durable after proving, failed submission, finalization, partial ledger application or reorganization. Cancellation or failed proof generation must not silently commit a proposed private transition. The present native helper sends the complete proof preimage to a loopback prover, so that prover is trusted with witness data. A proof's zero-knowledge property does not hide witnesses from the host or proof service which receives them. [Native proof assembly](../../scripts/zkir/native-contract.mjs), [runtime materialization](../../scripts/zkir/native-runtime.mjs), [proof preimage contents](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/transient-crypto/src/proofs.rs#L715).

## Native ledger composition obligations

Full ZKIR coverage does not itself implement a contract runtime. The ledger constructs proof statements, partitions calls, interprets state effects and validates their composition. Each obligation below needs independent positive and adversarial cases before broader support claims.

| Obligation | Native contract to satisfy | Required acceptance cases |
| --- | --- | --- |
| Artifact/key identity | Deployed entrypoint operation, IR, prover key, verifier key and versioned manifest agree | Reject wrong key, wrong entrypoint, missing operation and inconsistent artifact hashes |
| Call binding | Proof binding includes contract address, entrypoint, transcript gas/effects, guaranteed instruction count and parent intent commitment | Alter each bound component after proof generation and require rejection |
| Communication commitment | Commit to canonical ordered call input/return encodings with fresh randomness. ZKIR's optional flag must match the contract-call proof convention | Matching typed caller/callee values succeed. Wrong input, return, order, width or commitment fails |
| Transcript correspondence | Bind VM opcodes, alignment, operands, read results and write values, retaining per-op activity/skip groups | Reject regrouped activity, wrong skip widths, stale reads, changed opcodes, changed alignments and unbound computed values |
| Guaranteed/fallible partition | Use the ledger cost model, checkpoints, transcript versions and segment lifetime rules | Exercise full application, permitted partial application, checkpoint boundary failures and wrong declared costs |
| Cross-contract calls | Match callee address, entrypoint hash, communication commitment, call order and sequence, caller context and segment lifetime | Two-call positive case, wrong callee/entrypoint/commitment, reordered calls, duplicate/missing claims, forbidden call graph and wrong segment context |
| State and effects | Execute against the correct charged state and native context. Preserve read/write order, map absence/member semantics and effect accounting | Concurrent/stale-state rejection, nested state updates, ordered effects and exact fetched post-state bytes |
| Assets and events | Construct the native token claims/offers, conservation/accounting rules, event schema/version and public payloads | Mint/spend/receive/change tests, invalid authorization, incorrect token/amount, malformed event and disclosure rejection |
| Maintenance and lifecycle | Respect versioned verifier/IR registration, authority threshold/counter and transaction/finality outcome | Authorized update succeeds, stale/incorrect signatures or counters fail, old/new key behavior is explicit |

The ledger builds the public statement as binding input, communications commitment, then guaranteed and fallible program fields. It constructs private/public transcript vectors through typed aligned values and `Popeq` reads, and overwrites the initial placeholder binding input during proving. [Proof construction](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/ledger/src/construct.rs#L475), [public statement and binding input](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/ledger/src/verify.rs#L2083), [communications commitment](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/ledger/src/construct.rs#L994).

Inactive ZKIR activity rewrites the ledger program into normalized noops and adjusts declared cost. Flattening public fields while losing activity grouping therefore changes more than a host convenience structure. The ledger rejects zero-width or adjacent unnormalized noops and checks transcript gas limits. [Activity rewriting and cost adjustment](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/ledger/src/prove.rs#L254), [well-formedness checks](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/ledger/src/verify.rs#L1960).

The native partitioner requires a forest of calls and rejects cycles or multiple parents. The ledger separately correlates claimed sequence IDs with call positions and checks guaranteed/fallible caller-callee lifetimes. These are concrete restrictions on composability, not unrestricted recursion or arbitrary re-entry. The compiler and runtime should express the supported native composition model and reject unsupported graphs with useful diagnostics. [Partitioning](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/ledger/src/construct.rs#L1003), [call identity matching](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/ledger/src/structure.rs#L2969), [sequence and context checks](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/ledger/src/verify.rs#L1034).

Native state/event instructions and maintenance operations live outside the ZKIR instruction enum. Their inclusion in the target does not depend on Compact syntax exposure. Precise methods and overloads still need a ledger inventory alongside the ZKIR matrix. The comparison inventory already records many ledger ADT and SDK lifecycle headings, but its headings are not exhaustive executable semantic cases. [Native VM operation definitions](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/onchain-vm/src/ops.rs), [versioned maintenance bindings](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/ledger-wasm/src/contract.rs#L259), [minimum comparison baseline](compact-equivalence-baseline.md).

## Existing evidence and next bounded packages

The existing Native/Bool claim is a source-driven accepted development-ledger workload. Fresh 3.2.1 native keygen and the independent 3.2.1 checker accept its relation and preimage. The isolated ledger finalized deployment at height 1012 and claim at 1015, with 21 guaranteed VM operations and no fallible operations. Five invalid witnesses fail the checker. The replay result is a host guard rejecting against fetched spent state, not a second ledger-submitted transaction. Exact post-state bytes and receipt identities are recorded in [machine qualification evidence](../../tests/zkir321/qualification-evidence.json).

The intermediate-Jubjub fixture proves a narrower result: old keygen reproduces the missing-chip failure, new keygen succeeds, the official checker accepts the fixture, and the official WASM prover produces a standalone proof. No Jubjub source type or ledger call was added. The Boolean fixture independently tests ten raw-ZKIR semantic cases and key generation. It does not implement source deserialization or general guarded source execution. [Qualification details](../development/zkir-3.2.1-qualification.md), [raw fixtures](../../tests/zkir321).

Recommended next packages have explicit boundaries:

1. Establish producer well-formedness and guarded disclosure rules before adding source effects under secret conditions. Cover single assignment, exact types/widths, Boolean assertion preconditions, transcript/output structure, explicit release rules and data/control-flow rejection. Exit evidence includes adversarial witness constraints and compile-time disclosure failures, not only successful preprocessing.
2. Finish portable scalar/byte ABI and ordinary bounded computation. Keep current scalar work separate from typed Bool/Byte/Bytes support, byte selection lowering and canonical composite encodings. Add source semantics, two-host ABI fixtures, invalid encodings, official proofs and one ledger round trip per new representation.
3. Close native scalar state and guarded activity. Add unsupported map read/update cases, define activity correspondence for each VM opcode, then test public branches, explicitly released secret branches and rejected unreleased secret branches against exact ledger state.
4. Deliver one native two-contract call with nonempty typed inputs/returns. Bind communication commitments and manifest interfaces. Add wrong-key/address/entrypoint/order/segment/commitment cases and forbidden graph diagnostics before extending composition.
5. Expand cryptographic families from the full native matrix. Start with exact byte/hash alignment and domain vectors, then each curve field/point/conversion overload and signature construction. Preserve producer preconditions, malformed point/limb cases and per-family proof/ledger boundaries. Deprecated instructions need a compatibility policy and replacement-equivalence tests, not fresh unchecked emission.
6. Add native assets, events and maintenance in separate ledger slices. Each slice includes its canonical metadata, disclosure obligations, expected effects, rejected malformed transactions and finalized acceptance. A foreign-curve raw proof or a token helper in a dependency does not complete these slices.

No operation, type or library family is excluded merely because Compact does not expose it. Conversely, an unsupported or undefined raw opcode combination should not become an unsafe public Lean primitive. A safe implementation either expresses the supported semantics with proven preconditions and tested lowering, provides a verified replacement, or rejects the combination explicitly until the missing path is implemented.

Inventory validation compared the ordered instruction and type names directly with both pinned Rust enums. All 62 source entities match. The 276 row/case IDs are unique, all source/requirement/evidence references resolve, and 29 source-file SHA-256 values match the pinned checkouts. This research ran no new compiler conformance, proving or ledger transactions. Its runtime evidence comes from the previously recorded qualification workloads.
