# Nightlean portable runtime and artifact boundary

Research checked on 2026-11-16. This note recommends an architecture and a bounded next experiment. No native runtime implementation or mobile/WASI build was attempted.

## Decision

Keep the compiler in Lean. Define a language-neutral typed witness ABI and versioned execution plan, then implement one Rust reference runtime over Midnight's Rust libraries. Expose optional C, TypeScript, Kotlin and Swift adapters. Treat WebAssembly as an additional runtime packaging target and an optional format for deterministic application witness programs.

A full application bundle should include the circuit artifacts, execution plan, witness schema, optional executable witness program, target profile, keys and manifest. Producing this bundle requires distinct compiler, target key-generation and packaging stages. A private secret or Merkle path belongs to a per-call witness instance, never the public bundle.

The broader goal is feature equivalence with a pinned Compact release through the Lean compiler and native ZKIR path. The current claim and its expression/operation subset qualify one runtime slice. They do not establish feature parity. Extend the typed ABI, plan and shared runtime with the language capability inventory, preserving one execution implementation across host bindings.

This recommendation follows the current implementation: the Node scripts call Rust-backed WASM packages for cryptography and ledger semantics, and add a small Nightlean plan interpreter around those packages. The reusable Rust interfaces already exist. A host-neutral wrapper has not yet been implemented or qualified. [Nightlean runtime](https://github.com/awjreynolds/nightlean/blob/da3ffa3b61b0948768ca370b2abc391575e1dbae/scripts/zkir/native-runtime.mjs#L1-L86) [Rust query execution](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/onchain-runtime/src/context.rs#L905-L1000)

## What currently needs Node

The checked source baseline is Nightlean `da3ffa3b61b0948768ca370b2abc391575e1dbae`, standalone ZKIR 3.2.0 commit `446c7fecc6bd41dab99ebe89ab404e9d077d11a9`, and ledger source commit `a2b30128ca4b660b73a068e29b56b48ede8c9a74`. The installed ledger JavaScript package is `@midnight-ntwrk/ledger-v9` 1.0.2. The inspected Rust workspace labels its ledger crate 1.0.1. These identifiers are separate pins, and source inspection alone does not establish a byte-for-byte provenance match between this checkout and the npm binary. [Nightlean assembly](https://github.com/awjreynolds/nightlean/blob/da3ffa3b61b0948768ca370b2abc391575e1dbae/scripts/zkir/native-contract.mjs#L1-L42) [Ledger crate metadata](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/ledger/Cargo.toml#L1-L8)

| Responsibility | Current implementation | Proposed owner |
| --- | --- | --- |
| Supply secret, siblings and direction bits | Application provides `config.inputs`. There is no general witness callback registry in the current runtime. | Host secret provider through the typed ABI. |
| Evaluate expressions needed to construct the call | `environment` and `evaluate` interpret compiler-emitted expressions. `materialize` resolves state reads and emits Impact operations. | Shared Rust plan interpreter. |
| Derive internal circuit witness values | ZKIR preprocessing consumes the private/public vectors and evaluates the emitted relation, including arithmetic and hash instructions. | Upstream ZKIR, reused by Rust. |
| Execute state operations and charge costs | Ledger `QueryContext`, transcript partitioning and transcript replay behind WASM bindings. | Upstream Rust ledger/runtime. |
| Construct serialized checker/prover input | JavaScript orchestration calls ledger serialization helpers. | Rust preimage adapter using upstream representations. |
| Produce a cryptographic proof | Optional loopback proof-server request from the script. | Separately selected native in-process or local-service provider. |
| Read files, hash artifacts, arrange bundle | Node filesystem, crypto and CLI functions. | Build/package tooling, independent of application runtime. |

The first three rows distinguish three meanings of “witness.” Host-supplied private values are inputs. Application off-chain computation supplies or derives those inputs. Circuit preprocessing derives the internal values required by the proving relation. An application witness WASM module addresses the second responsibility. Such a module does not replace ledger transcript construction or ZKIR preprocessing. [Runtime evaluation and materialization](https://github.com/awjreynolds/nightlean/blob/da3ffa3b61b0948768ca370b2abc391575e1dbae/scripts/zkir/native-runtime.mjs#L12-L74) [ZKIR private-input consumption](https://github.com/midnightntwrk/midnight-zkir/blob/446c7fecc6bd41dab99ebe89ab404e9d077d11a9/zkir/src/ir_vm.rs#L229-L255) [Private-input instruction](https://github.com/midnightntwrk/midnight-zkir/blob/446c7fecc6bd41dab99ebe89ab404e9d077d11a9/zkir/src/ir_vm.rs#L442-L469)

Node is required by the current `.mjs` entrypoints and their packaging. No reviewed source establishes Node as a requirement of the circuit relation, Impact execution, proof-preimage format or native prover. The compiler already emits symbolic expressions, state descriptions, ordered reads and operations as data. Extending and validating this format offers a smaller change than generating equivalent JavaScript, C++, Kotlin and Swift execution engines. [Compiler plan emission](https://github.com/awjreynolds/nightlean/blob/da3ffa3b61b0948768ca370b2abc391575e1dbae/Nightlean/Compiler.lean#L146-L201)

Two details need explicit parity coverage. The JavaScript `proofDataIntoSerializedPreimage` helper creates a checker preimage with zero binding input and zero communication randomness. The actual call prototype contains fresh communication randomness, and transaction proving later fills the binding input. Comparing those two preimages without matching their construction context gives a false failure. Also, the Rust name `ProofPreimageVersioned::V2` does not mean ZKIR version 2. The proof server separately dispatches an `ir-source[v3-generic]` circuit to ZKIR v3. [Checker preimage helper](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/onchain-runtime-wasm/src/primitives.rs#L226-L280) [Call preimage](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/ledger/src/construct.rs#L539-L555) [Version dispatch](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/proof-server/src/versioned_ir.rs#L43-L94)

## Typed ABI and execution ownership

The following is a proposed contract, not an existing API.

Define named witness requests and ordered results with stable field identifiers, exact types, lengths, visibility and schema version. Start with the existing `Native` field and `Bool`, then add bounded bytes, arrays, records and optional values only alongside compiler and runtime support. Use canonical decimal fields for JSON fixtures. For a binary ABI, select a fixed-width field encoding and specify byte order, modulus rejection and boolean encoding. Do not pass language `BigInt`, JSON numbers or Rust struct layouts across the binary boundary.

Separate `prepare`, `supply-witness`, `resume`, `finish` and `cancel` concepts. A host satisfies a witness request from its local storage, wallet or user interaction and supplies a typed result. For the current claim, all private values are supplied together, so the first implementation needs no asynchronous callback machinery. A future resumable interface avoids blocking a mobile UI or exposing Rust futures through C. The runtime validates responses and constrains them through the emitted circuit, regardless of provider language.

The core owns plan validation, expression semantics, field/hash encoding, state-read ordering, Impact construction, transcript partitioning and preimage assembly. Host adapters own private storage, wallet access, user interaction, network state retrieval, entropy and scheduling. A private-state update is a proposal associated with a call, committed by the host after accepted transaction outcome. WASM imports or native callback tables express these capabilities explicitly.

Use opaque runtime handles and owned byte buffers for C, with documented allocation/free functions, length limits, cancellation, error codes and thread rules. C++ consumes the C surface. Kotlin/Android adds a JNI adapter. Swift/iOS consumes a C module or generated wrapper. TypeScript provides typed application calls and provider contracts over an optional web adapter. These adapters should delegate execution to the shared core rather than reproduce its semantics.

Preserve Midnight's actual cryptographic encodings. The current `poseidon2` expression calls the pinned ledger `transientHash` wrapper, which converts an aligned value through `ValueReprAlignedValue` before hashing. The Rust implementation uses Midnight's `PoseidonChip`. A library advertised as “Poseidon2” is not enough evidence of compatibility. Likewise, a bool represented as a circuit field and a bool represented as an Impact bytes-aligned value occupy different roles. [Hash wrapper](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/onchain-runtime-wasm/src/primitives.rs#L340-L350) [Hash primitive](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/transient-crypto/src/hash.rs#L75-L88) [Nightlean alignment](https://github.com/awjreynolds/nightlean/blob/da3ffa3b61b0948768ca370b2abc391575e1dbae/scripts/zkir/native-runtime.mjs#L3-L22)

## Rust core versus WASM first

A Rust core gives the shortest path to direct use of the existing ledger and ZKIR libraries. Native host bindings remove a mandatory JavaScript engine from Rust, C++, Android and iOS applications. Each target still needs a build, packaging and dependency audit. This research does not qualify any mobile target.

WASM offers a portable executable format for deterministic application computations and a sandbox boundary when the host deliberately limits imports. WIT describes typed interfaces, imports and exports, including records and resources. WIT does not define witness behavior, secret access or transaction semantics. Rust's `wasm32-wasip2` emits a component and requires a component-capable WASI Preview 2 runtime. [WIT reference](https://component-model.bytecodealliance.org/design/wit.html) [Rust WASI target](https://doc.rust-lang.org/rustc/platform-support/wasm32-wasip2.html)

Existing Midnight WASM packages depend on `wasm-bindgen`, JavaScript values/promises and JavaScript randomness integrations. Their existence proves a web-oriented WASM route, not a WASI/component or arbitrary embedded-engine route. Rebuilding a portable component requires replacing those boundary assumptions. The native ledger graph also includes Tokio and Rayon, and storage includes system-facing dependencies. Do not promise one build across browser, WASI, Android and iOS before measuring those graphs. [Ledger WASM dependencies](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/ledger-wasm/Cargo.toml#L15-L48) [ZKIR WASM dependencies](https://github.com/midnightntwrk/midnight-zkir/blob/446c7fecc6bd41dab99ebe89ab404e9d077d11a9/zkir-wasm/Cargo.toml#L11-L25) [Native ledger dependencies](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/ledger/Cargo.toml#L24-L67) [Storage dependencies](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/storage/Cargo.toml#L20-L40)

Therefore, make the ABI and conformance vectors portable first. Build a Rust runtime first, then attempt a small WASM host comparison. A compiler-generated witness WASM program remains optional for source-defined deterministic application logic. Native host functions remain necessary for secrets, external state and interaction. Choosing Rust reflects concrete upstream implementation reuse, not an evidenced claim about the whole ecosystem moving away from TypeScript.

## Artifact bundle stages

| Stage | Outputs and responsibility |
| --- | --- |
| Lean source compilation | ZKIR JSON, versioned execution plan, witness/public ABI, state schema, source maps where available, compiler metadata. Optional witness IR or deterministic executable program later. |
| Pinned target preparation | ZKIR binary, prover key and verifier key produced by the upstream target key generator. Record compiler/prover versions, parameter identity, commands and artifact hashes. |
| Runtime packaging | Reference runtime version, optional platform libraries, optional witness WASM/native module, TypeScript bindings, and other host adapters as separate packages. |
| Bundle verification | Content-addressed manifest binds source/IR hashes, plan and ABI hashes, target compatibility profile, key hashes and optional witness-module hash. Reject mixed bundles before execution. |
| Private call execution | Host private inputs, private-state proposals, proof preimages and runtime session data. Keep these outside the distributable bundle. |

Today Lean emits relations, plans and metadata. The official ZKIR CLI performs key generation. A future `nightlean build` command should orchestrate both stages without describing target keys as direct Lean compiler outputs. Pin parameter files and build provenance, then test reproducibility before claiming deterministic byte-identical key generation. [Compiler output](https://github.com/awjreynolds/nightlean/blob/da3ffa3b61b0948768ca370b2abc391575e1dbae/Nightlean/Compiler.lean#L146-L201) [ZKIR key generation](https://github.com/midnightntwrk/midnight-zkir/blob/446c7fecc6bd41dab99ebe89ab404e9d077d11a9/zkir/src/main.rs#L210-L270)

A network deployment profile belongs alongside artifact compatibility, with its own identity. Runtime ledger parameters and public state change over time, so a bundle's target profile does not replace validation of the call's actual network, parameter snapshot and state snapshot.

The present development assembly writes `runtime-config.json` beside keys and plans. This includes configured private inputs and is a local fixture convention, not a distributable bundle design. Public artifact packaging must exclude this file and all concrete witness/preimage material. [Current assembly outputs](https://github.com/awjreynolds/nightlean/blob/da3ffa3b61b0948768ca370b2abc391575e1dbae/scripts/zkir/native-contract.mjs#L23-L40)

## Dependency and secret handling boundaries

Standalone ZKIR patches core dependencies to ledger commit `9a8777c4d035fc7f38ae286bcf5f8656668efd9f`. The inspected ledger workspace patches external ZKIR's dependencies to its own in-tree crypto/serialization crates. Follow the latter precedent in the proposed combined workspace, then inspect and lock the resolved dependency graph. Duplicate crate sources create distinct Rust types even with similar names. A tagged serialization bridge is a fallback when source unification fails, subject to golden-vector checks. Never silently substitute the ledger checkout's older local `zkir-v3` crate for standalone 3.2.0. [Standalone dependency pins](https://github.com/midnightntwrk/midnight-zkir/blob/446c7fecc6bd41dab99ebe89ab404e9d077d11a9/Cargo.toml#L29-L42) [Ledger unification patches](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/Cargo.toml#L65-L74) [Ledger ZKIR selection](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/ledger/Cargo.toml#L37-L38)

Both inspected workspaces declare Apache-2.0. This establishes their declared license, not the complete license inventory of a mobile or WASM distribution. Capture the resolved transitive licenses and bundled parameter/key provenance with each runtime release. [ZKIR license declaration](https://github.com/midnightntwrk/midnight-zkir/blob/446c7fecc6bd41dab99ebe89ab404e9d077d11a9/Cargo.toml#L12-L14) [Ledger license declaration](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/Cargo.toml#L1-L4)

Parameter access is a provider interface. The built-in data provider uses a filesystem cache and SHA-256 verification, with fetch behavior. A mobile host needs an explicit cache location, bounded downloads and a background scheduling policy. A WASI component needs an explicit capability or host-supplied bytes. Keep parameter acquisition out of deterministic witness evaluation. [Parameter provider](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/transient-crypto/src/proofs.rs#L56-L78) [Cache and integrity contract](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/base-crypto/src/data_provider.rs#L36-L64)

`ProofPreimage` derives zeroization on drop. This does not erase every copied host string, serialized buffer, WASM memory region or intermediate VM allocation. Keep production witness material in owned, short-lived buffers, suppress sensitive tracing, specify clear/free behavior and document residual copies across adapters. Proving in a local native library removes one transport boundary, but leaves proof-preimage handling and memory lifetime as part of the confidentiality design. [Preimage ownership and derives](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/transient-crypto/src/proofs.rs#L709-L742)

## Small next experiment

Build one Rust executable in an isolated experiment with the existing emitted private-claim plan, ZKIR, keys, ledger parameters and test inputs. Keep the Lean compiler unchanged.

The initial direct dependency set is `midnight-ledger-v9`, `midnight-onchain-runtime`, `midnight-base-crypto`, `midnight-transient-crypto`, `midnight-serialize`, `midnight-storage`, and `midnight-coin-structure` from ledger commit `a2b30128ca4b660b73a068e29b56b48ede8c9a74`, plus `midnight-zkir` from commit `446c7fecc6bd41dab99ebe89ab404e9d077d11a9`. Add JSON parsing and test RNG support. The runtime re-exports its state, operations and result-mode types, so a separate direct onchain-VM dependency is unnecessary for the initial adapter. Use `storage::db::InMemoryDB`, `base_crypto::fab::{AlignedValue, Alignment, Value}`, `transient_crypto::fab::{AlignedValueExt, ValueReprAlignedValue}` and `FieldRepr` rather than reproducing their wire layouts. This is a proposed dependency set, not a tested Cargo manifest. [Runtime re-exports](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/onchain-runtime/src/lib.rs#L22-L45) [Existing wrapper imports](https://github.com/midnightntwrk/midnight-ledger/blob/a2b30128ca4b660b73a068e29b56b48ede8c9a74/onchain-runtime-wasm/src/primitives.rs#L14-L36)

1. Resolve a locked Rust dependency graph using standalone ZKIR 3.2.0 and the pinned ledger libraries. Record exact source revisions and reject mock-verification features.
2. Implement only the current plan expression/operation subset. Validate the ABI, create the same state, supply the same secret and path, execute Impact, partition transcripts and serialize the checker preimage without Node.
3. Run `ProofPreimage::check(&ir)`. Compare private/public field sequences, per-op activity groups, normalized Impact operations, transcript partitions, costs and predicted state with the existing JavaScript fixture. For randomized call bytes, inject the same test-only randomness and time into both harnesses or compare the relevant semantic fields.
4. Repeat wrong-secret, path, direction, root and nullifier cases, malformed/noncanonical inputs, wrong plan/key hashes and replay against the post-claim state. Rejection must leave input state unchanged.
5. Separately compare actual randomized call preimages and binding-input treatment. A successful standalone checker-preimage test does not qualify final transaction proof construction.
6. Add a second, explicitly scoped test for native in-process proving with local pinned parameters and keys. Record proof verification, time and peak memory. Proving independence and ledger acceptance are separate outcomes from witness-runtime independence.
7. If the dependency graph supports a bounded attempt, package the same small computation/runtime surface as WASM and run the same vectors in one non-JavaScript host. Record imports, artifact size, memory and unsupported dependencies. Stop at a concrete build blocker rather than expanding the experiment into a runtime port.

Success for the first experiment means the existing claim's witness supply, deterministic expression execution, Impact/state work, transcript partitioning, proof-preimage construction and ZKIR checking all execute in Rust without a Node process. Browser bindings, Android/iOS packaging, general witness callbacks and a WASI component become subsequent qualification work against the same ABI and vectors.
