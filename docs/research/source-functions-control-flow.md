# Source functions, modules and guarded execution

Research slice for issue 35, checked on 2026-11-16. All upstream source references below pin Compact 0.36.1 at commit `7fa3a117c5e7efe9d2c51da04263e5f0b3509144`. This is a source-derived implementation contract and ticket breakdown. No Compact executable was installed or run. None of the semantic cases below has an execution result from this research.

The objective is the full pinned native ZKIR v3 feature set implemented and running through a Lean-written compiler and a native, host-neutral runtime. Compact feature-equivalence is the minimum comparison surface. Native-ledger composition and source capabilities beyond Compact remain in scope wherever the native interfaces support them safely. The packages below preserve functions, generics, modules, loops and privacy analysis. Learn from Compact's proven compiler engineering patterns and adapt them to Lean, without requiring Compact syntax, executables or runtime packages.

Separate three contracts: the native backend's supported instruction/interface set, Noctium's source-language semantics, and Noctium's mandatory disclosure policy. Native instruction support never authorizes private-to-public flow by itself. Compact restrictions below document upstream comparison behavior, not a ceiling on native capability. An extension should have an explicit source rule, rationale and native acceptance evidence. A deliberate semantic difference needs tests and documentation.

## Functions and effects

Named functions require declared parameter and result types. Argument types must be subtypes of the selected declaration. Argument expressions evaluate left to right, exactly once, before the function body. Pattern-bound parameter components inherit the declared parameter component types. A return exits the nearest anonymous function or enclosing named function. An absent return value or fall-through yields unit `[]`, which must fit the declared result type. Direct and indirect recursive circuit calls are rejected in the analyzed call graph. Functions are not first-class values. [REF](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/doc/compact-reference.mdx#circuit-and-witness-calls), [TYPE](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/analysis-passes/infer-types.ss#L363), [REC](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/analysis-passes/reject-recursive-circuits.ss).

Anonymous functions accept optional parameter and result annotations. Missing parameter annotations derive from actual arguments. Missing result annotations derive from the body. Anonymous functions have no generic parameters. Their lexical environment remains visible. They are permitted as direct callees and map/fold operators, without introducing arbitrary runtime function pointers or escaping closures. [REF](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/doc/compact-reference.mdx#circuit-and-witness-calls), [anonymous inference](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/analysis-passes/infer-types.ss#L511).

Overload resolution is scope-sensitive. EXP groups visible declarations from inner to outer lexical scopes, removes repeated bindings introduced through imports, and filters generic argument arity/kinds. TYPE searches these scope groups in order. A group with no compatible value-argument signatures falls through to the next group. One compatible candidate wins. Multiple compatible candidates within the first matching group produce ambiguity, with no smallest-type tie-break. A non-function binding stops visibility through its scope. A flat candidate list across all scopes would change this behavior. [EXP lookup](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/analysis-passes/expand-modules-and-types.ss#L483), [TYPE selection](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/analysis-passes/infer-types.ss#L392).

Purity is transitive. Ledger access, event emission, witness calls, cross-contract calls and calls to impure helpers make a function impure. A declared-pure function containing those operations is rejected. The purity pass traverses branch syntax before circuit simplification, so an effect inside a literal-false branch is still relevant to purity. This differs from both runtime execution and the constant-aware disclosure analysis described below. Unused-function pruning precedes recursion/purity analysis, so unreachable-declaration diagnostics need dedicated cases instead of a blanket promise about all source text. [PURE](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/analysis-passes/identify-pure-circuits.ss), [pass ordering](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/analysis-passes.ss).

For Noctium, effect summaries must distinguish witness/private-state access, ledger reads, ledger writes, assertions/fallible casts, events and cross-contract calls. The summary is an implementation proposal, not an upstream data structure. A Boolean pure/impure flag alone cannot preserve execution order or identify privacy sinks.

## Guarded execution contract

Conditional expressions require a Boolean condition. Both branches are statically checked, even when the condition is a literal. The compiler accepts the result types only when one branch type is a subtype of the other, then uses the wider type. Merely having some unrelated common supertype is insufficient for this rule. Statement branches require a Boolean condition without requiring matching discarded result types. [TYPE conditional paths](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/analysis-passes/infer-types.ss#L1096), [expression rule](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/analysis-passes/infer-types.ss#L1239).

At runtime, evaluate the condition first and execute exactly one branch. An inactive branch invokes no witness callback, changes no private state through a callback, performs no ledger query or mutation, emits no event and makes no contract call. Its assertions and dynamic narrowing failures do not fail the enclosing invocation. Static errors still reject the program. `and` skips its right operand when the left operand is false. `or` skips its right operand when the left operand is true. [BOOL](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/frontend-passes/eliminate-boolean-connectives.ss), [HOST statement branches](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/typescript-passes/print-typescript.ss#L2367), [HOST conditional expressions](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/typescript-passes/print-typescript.ss#L2613).

The proof contains a finite relation for both paths. For parent execution guard `g` and condition `b`, the active guards are `g and b` and `g and not b`. Assertion lowering enforces `not g or assertion`. Witness results use guarded private inputs, and ledger instructions carry their execution guard. This does not authorize executing both branches on the host and discarding one result. Nor does the presence of unused circuit slots authorize an inactive branch to consume an extra witness response. [GUARD](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/circuit-passes/reduce-to-circuit.ss#L75), [witness inputs](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/zkir-v3-passes/reduce-to-zkir.ss#L117), [Impact guard](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/zkir-v3-passes/reduce-to-zkir.ss#L659).

Noctium's existing eager `select` is a value operation. Keep its established behavior explicit. Add structured conditional execution instead of rewriting effectful branches to eager selection. Eager selection is safe as a final merge of already guarded, defined result values. Inactive circuit inputs and primitives still need valid defaults where the native backend lacks guards. Upstream has explicit guard workarounds for such cases, so blanket claims of backend guard support would be premature. [Existing evaluator](../../scripts/zkir/native-runtime.mjs), [upstream workarounds](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/circuit-passes/missing-guard-workarounds.ss).

An active witness receives the current ledger view, current private state and contract address, then returns next private state and a result. Generated code records private transcript outputs after checking the result. The source assigns the next private state before result validation. That order is evidence about upstream local context mutation, not a guarantee of external storage rollback or a reason to copy the mutation order. The portable ABI must document invocation-local state and failure/commit boundaries separately. Arbitrary external side effects inside an untrusted callback cannot be undone by circuit control flow. Inactive-branch tests should supply a registered callback and verify zero invocations, rather than assume a missing callback binding is valid. [HOST witness wrapper](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/typescript-passes/print-typescript.ss#L1862).

## Disclosure rules with source-level distinctions

PRIV tracks origins through values and control dependencies. Origins include constructor parameters, exported function parameters and witness return values. Arithmetic, comparisons, casts, serialization and ordinary hashes preserve origin information. Struct/tuple components retain separate origin information where the analysis represents them separately. Index selection adds index-origin dependence. Ordinary helper calls propagate origins between actual parameters, body and return values. [PRIV expressions](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/analysis-passes/track-witness-data.ss#L622).

The public sinks have different checks:

| Sink | Required analysis |
| --- | --- |
| Ledger operation, including a read | Reject undisclosed control origins which determine whether the operation executes. Check each argument using the ADT operation's disclosure annotation |
| Event | Check both control origins and all payload origins |
| Cross-contract call | Check control origins, contract reference and every argument |
| Exported return | Check witness-return origins in returned value and control path. The pinned implementation filters out constructor/exported-argument origins here |
| Witness call | Produces an untrusted witness-origin value. Calling a witness is impure, but is not itself one of the public sinks above |
| Assertion | Propagate evaluation of its argument, then produce unit. Assertion success/failure is not treated as an ordinary public disclosure sink by this analysis |

The exported-return distinction is narrower than some reference prose. Returning an exported argument alone does not require explicit disclosure under this pass. Returning a witness result does. Both still require disclosure when used in an annotated ledger argument, event or cross-call. This is an upstream comparison fact, not Noctium's authorization policy and not a claim of complete information-flow security. In particular, Noctium must not adopt the argument-origin exemption for a value declared private when the result enters a public output. The reason is the user's explicit no-unauthorized-disclosure requirement, and the corresponding rejection cases appear below. [Sink handlers](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/analysis-passes/track-witness-data.ss#L857), [return filtering](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/analysis-passes/track-witness-data.ss#L898).

Explicit disclosure clears origin tracking for the wrapped value. It neither publishes the value nor bypasses a proof constraint. Evaluating the expression inside the wrapper still performs its own sink checks, so wrapping a whole effectful conditional does not retroactively authorize a private guard controlling a ledger operation. Disclosing the guard before branching authorizes that control dependence. Disclosing only the written payload does not. Commitments are annotated as suppressing origin propagation, with the library's randomness assumption. Hashes are not. [PRIV clearing and conditional paths](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/analysis-passes/track-witness-data.ss#L469), [native annotations](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/midnight-natives.ss), [disclosure reference](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/doc/explicit-disclosure.mdx).

For a statically known Boolean, PRIV analyzes the selected branch. For an unknown Boolean, PRIV analyzes both branches and merges origins, including the condition's origins in the resulting value. A runtime false private guard does not excuse an undisclosed public effect. Conversely, a literal-false branch containing such an effect is skipped by disclosure analysis after ordinary type checking. The analysis recognizes Boolean literals and propagated Boolean abstract values, not all arithmetic truths. For example, an equality comparison is represented conservatively rather than proved true by this pass. [PRIV branch rules](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/analysis-passes/track-witness-data.ss#L607).

### Mandatory Noctium disclosure policy

The user explicitly requires compiler rejection of unauthorized private-state disclosure through guarded public effects. Adopt a source policy covering both data and control dependence, independently of Compact's implementation exceptions:

- Label private parameters, witness/provider results and private-state reads as private origins. A provider's host language or claim of trust does not clear the origin. Explicitly public inputs and authenticated ledger reads have public origins. Invocation-local state updates preserve the origins of their stored values.
- At every public state mutation, public circuit output, event and contract call, check both the payload's origins and the active control path's origins. A private predicate deciding whether to write the public constant 1 is unauthorized unless the predicate's disclosure is acknowledged. Nested guards accumulate control origins. Disclosing the payload alone is insufficient.
- Public query selection and transcript-visible reads also need control/index checks because selecting which state to read exposes information. Cross-contract targets, entrypoint selection and public argument/communication material are sinks. If a native interface supports a private cross-call argument, specify and prove its confidentiality boundary separately rather than copying Compact's all-arguments-disclosed rule.
- A disclosure construct authorizes an identified value/control dependency at a visible source location. It must not clear unrelated provider results, sibling fields or later private-state reads. Native cryptographic operations receive explicit propagation/declassification rules. No blanket rule should classify a native hash or opcode as safe merely because the backend supports the operation.
- Validate this policy before artifact generation. The runtime must enforce the artifact's declared public/private schema and reject schema mismatches. Hand-written low-level artifacts require a separately stated trust boundary, since a source compiler cannot enforce policy on artifacts bypassing the compiler.

This policy strengthens the upstream exported-return behavior when Noctium declares an argument or output private/public explicitly. Treat that as a documented safety-policy difference with tests for each changed acceptance decision. An exported function's local result and its public proof output must be distinct interface concepts so private local results are not accidentally made public.

Assertions and failure channels require a separate claim. A proof necessarily reveals satisfaction of its public relation. A private assertion, rejected transaction, callback error, proof failure, timing difference or early return may reveal more to an observer than the value-flow checker models. The upstream assertion rule is not evidence of noninterference for these channels. Define which invocation outcomes are public, prevent private payloads in public diagnostics, and state the remaining observational limits. Do not label ordinary private proof predicates as automatically public values or claim complete confidentiality from data/control sink checks alone.

## Generics, module identity and bounded iteration

Generic parameters are compile-time types or natural numbers. Named functions, witnesses, modules, structs and aliases support them. Uses supply the complete argument list with matching arity and kinds. Natural arguments are literals or existing generic parameters, not arbitrary runtime expressions. Module parameters are visible to declarations inside the module. Anonymous functions and cross-contract interface methods are not generic. A top-level exported function must be monomorphic, and exported function names must be unique. Generic helper functions remain available through specialized wrappers. [REF generic rules](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/doc/compact-reference.mdx#generic-parameters-and-arguments), [EXP kind checks](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/analysis-passes/expand-modules-and-types.ss#L483).

Modules control visibility and declaration identity. Support private declarations, explicit export, selective import, renaming, prefixes and re-export. Repeated import of the same module and generic arguments reuses cached export bindings, including ledger identity. Distinct module definitions or specializations must not accidentally share ledger fields. Alias names do not create fresh module instances. Source module/type cycles are diagnosed. A new Noctium Lean-module mapping must preserve those identities and visibility rules without adopting Compact's file naming or search-path conventions. Includes splice declarations into the enclosing scope. They are a source-composition capability, not a requirement to parse `.compact` files. [EXP import cache](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/analysis-passes/expand-modules-and-types.ss#L759), [cycle detection](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/analysis-passes/expand-modules-and-types.ss#L431).

Loops have compile-time iteration counts. Range loops use natural constants/parameters, end-exclusive bounds, start no greater than end, each endpoint no greater than `2^248-1`, and count no greater than `2^24`. Equal bounds perform zero iterations. Sequence loops accept fixed vectors, vector-compatible tuples and bytes. A return escaping the loop is rejected, but a nested anonymous function has its own return scope. No unrestricted while loop, recursive circuit evaluation or iteration over an unbounded ledger collection is implied. [EXP loop bounds](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/analysis-passes/expand-modules-and-types.ss#L1243), [return restriction](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/frontend-passes/reject-for-return.ss).

Map accepts a function and one or more equal-length fixed sequences, then returns a vector of the function's results. Fold also evaluates an initial accumulator and requires the operator's first parameter and return type to be the same type. The initial value is a subtype of that accumulator type. Sequence expressions evaluate once, left to right, before index-ordered calls. Fold evaluates its initial value first. A zero-length map invokes no operator and returns an empty vector. A zero-length fold returns the initial value after evaluating sequence expressions. Witnesses are valid map/fold operators, so call counts and state threading matter. [TYPE map/fold](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/analysis-passes/infer-types.ss#L1567), [LOOP](https://github.com/LFDT-Minokawa/compact/blob/7fa3a117c5e7efe9d2c51da04263e5f0b3509144/compiler/circuit-passes/unroll-loops.ss).

## Semantic case register

The first table records proposed, source-derived Compact comparison expectations. The following Noctium policy cases state the user's stronger public-sink requirement. Implement both as independent value/effect traces, compile-time rejection fixtures and native proof/ledger checks where applicable. Error wording need not match Compact. Record the rationale and expected behavior for every deliberate difference in acceptance decisions.

| `NL-DISC-GUARD-CONSTANT` | Reject private guard controlling a write of constant 1. The operation's presence reveals the predicate even though the payload is public |
| `NL-DISC-GUARD-OUTPUT`, `NL-DISC-GUARD-EVENT`, `NL-DISC-GUARD-CALL` | Reject private control of public output selection, event presence or native ledger call selection. Native support for each operation does not authorize the information flow |
| `NL-DISC-NESTED` | A public outer guard does not clear a private inner guard. Disclosing one of two private guards does not authorize the other |
| `NL-DISC-PRIVATE-ARG-OUTPUT` | Reject a private parameter copied to a public proof output without disclosure. This deliberately differs from Compact's exported-return argument-origin exemption |
| `NL-DISC-PRIVATE-LOCAL-RESULT` | Allow a private local function result used only in a private relation. Export metadata must not automatically turn that result into a public output |
| `NL-DISC-QUERY-PATH` | Reject private selection of a transcript-visible read path without acknowledgement. Check branch presence and key/index selection |
| `NL-DISC-EXTENSION` | Adding a native opcode/ledger interface without an explicit origin/effect rule fails compiler capability validation. A valid backend lowering alone cannot enable an unchecked sink |
| `NL-DISC-FAILURE-CHANNEL` | Classify private assertion failure, host error and transaction rejection observability. Public diagnostics contain no private payload. Record which outcome/timing channels are outside the proved sink guarantee |
| `NL-DISC-AUTHORIZED` | An explicit disclosure at the correct data/control boundary permits the intended public effect. Rejecting every private-dependent program would fail the required functionality |

## Bounded implementation tickets

### SF-01: Typed named helpers and scope-aware call resolution

Implement callable declarations, parameters/results, lexical binding identity, call checking and transitive effect summaries in the Lean compiler. Support the current scalar/composite type registry without embedding backend-specific calls in the source model. Resolve overloads by lexical groups. Reject reachable recursion. Export only monomorphic unique entrypoint names. Preserve source spans through calls.

Prerequisites: typed value/subtype rules, including the pinned Uint equations. Exit: `FN-*` cases, reference evaluation of ordered helper calls, and native proof equivalence for a helper-composed scalar circuit. Effects unsupported by the backend must produce explicit capability diagnostics, not disappear. Anonymous functions and generic specialization belong to later tickets.

### CF-01: Structured conditional execution and portable branch traces

Add conditional statement/expression and short-circuit semantics to the source model, evaluator and portable plan. Keep eager select distinct. Carry active-path status through returns, assertions, narrowing and witness suspension/resumption. Reject all static errors before execution.

Prerequisites: SF-01 calling convention, portable witness ABI and invocation-local state policy. Exit: `CF-TYPE-*`, `CF-WITNESS-*`, `CF-ASSERT-INACTIVE`, `CF-CAST-INACTIVE`, `CF-SHORT-*` in two host implementations with matching result/error/effect traces. No native ledger branch support is claimed by this ticket alone.

### CF-02: Bind branch guards to native proofs and state transcripts

Lower structured control flow into the native relation and ordered Impact effects. Cover scalar cell/map operations first, with nested guards and inactive failure cases. Define witness-slot consumption and inactive defaults explicitly. Gate each additional primitive on demonstrated guard behavior.

Prerequisites: CF-01, current native transcript schema and ZKIR qualification. Exit: official checker/prover positive and adversarial guard cases, plus isolated-ledger `CF-LEDGER-INACTIVE`, `CF-NESTED-GUARD` and transcript-binding checks with exact final state. Event/cross-call cases remain linked requirements for those backend packages. This ticket must not claim support for every native primitive.

### DF-01: Track private data and control origins across functions

Implement component-aware origin propagation, helper-call summaries, explicit disclosure, native primitive annotations and sink checks. Distinguish compile-time Boolean knowledge from runtime branch outcomes. Apply the mandatory Noctium policy to public proof outputs, including private argument origins, while retaining Compact's different exported-return result as a comparison fixture. Diagnostics identify origin, sink and a useful path through calls/components.

Prerequisites: SF-01, structured branch semantics, typed composite traversal and an explicit primitive/ADT disclosure registry. Exit: `DISC-*` comparison cases with documented differences, all available `NL-DISC-*` sink cases, serialized diagnostics and field-by-field disclosure regressions. Event and native cross-call sinks must be registered before their language routes are enabled. Privacy analysis is mandatory for newly exposed public effects, not an optional final hardening step.

### DF-02: Audit disclosure coverage across native features and failure boundaries

Extend the origin/effect registry across the complete pinned ZKIR/native-ledger feature inventory. Each new operation declares its private inputs, public outputs/transcript effects, control dependence and any justified cryptographic declassification. Reject missing rules. Analyze provider/private-state reads, nested guards and native composition independently of Compact exposure. Record the reason for every allowed or rejected flow.

Prerequisites: DF-01, native capability inventory, portable provider schema and the composition interface specification. Exit: `NL-DISC-EXTENSION`, `NL-DISC-NESTED`, provider/state cases, one unauthorized/authorized pair for every public sink family, and a reviewed failure-channel contract. Demonstrate rejection before artifact emission. Native checker and ledger tests establish the relation between authorized public effects and the proved transcript. This ticket does not claim constant-time host execution or rollback of arbitrary callback side effects.

### GEN-01: Compile-time type/natural specialization

Add explicit generic parameters and stable specialization identities to functions, witnesses, structs and aliases. Support module-provided parameters as inputs to specialization. Reject kind/arity errors and preserve nominal identity. Ensure malformed recursive specialization fails within bounded compiler resources, with a diagnosed unsupported/recursive case rather than nontermination.

Prerequisites: SF-01 and a canonical type identity scheme. Exit: `GEN-*`, generic helper proof/evaluation cases and typed witness signature round trips. Generic runtime dispatch and escaping function values are separate source extensions, not requirements of this bounded package or forbidden native capabilities. The exact upstream behavior for endlessly expanding generic specialization was not established by this read-only investigation, so resource-limit behavior must be documented as a Noctium safeguard rather than asserted as byte-for-byte parity.

### MOD-01: Module visibility, specialization reuse and ledger identity

Map Lean modules/namespaces to explicit contract declarations and import/export views. Implement selective exposure, aliases, re-export and specialization reuse. Preserve one state identity for repeated imports of the same specialization. Define deterministic artifact names without using source aliases as state identity.

Prerequisites: GEN-01, declared state identity/layout and SF-01 lookup rules. Exit: `MOD-*`, deterministic manifest identities, two entrypoints sharing one imported state field, and a distinct-specialization case with separate fields. Filesystem composition and include-like capability need a documented Lean-native route, not Compact path resolution.

### ITER-01: Finite loops, anonymous operators, map and fold

Implement anonymous callable typing/capture and compile-time bounded iteration with ordered effects. Evaluate sequence expressions once before iteration. Preserve empty-sequence behavior and accumulator identity constraints. Check count/endpoints before allocating compiler structures.

Prerequisites: CF-01/02, SF-01, GEN-01 and vector/tuple/byte types. Exit: `ITER-*`, witness trace agreement across both hosts, and a small loop with guarded ledger effects accepted by the isolated ledger. Stress tests should verify early resource checks without constructing the maximum-size proof. Bounded source extensions beyond Compact require an explicit finite-circuit semantics and acceptance evidence. Compact's syntax and numeric limits are comparison points, not automatic limits on the full native target.

## Compiler engineering lessons to apply

The user explicitly asked to learn from Compact's implementation. These are reusable engineering patterns, with concrete Noctium applications. Source analysis here does not copy implementation code. Any future code reuse needs a license/provenance review for the exact files involved.

| Compact lesson | Noctium application | Verification requirement |
| --- | --- | --- |
| Typed intermediate languages separate expansion, type checking, effect analysis and lowering | Use small Lean-owned passes with explicit input/output invariants. Place privacy validation before public artifact emission. Keep proof-target details out of source name resolution | Check each pass invariant and preserve source spans. Do not rely solely on the final generated artifact |
| Type normalization uses inclusive maxima consistently, even where prose is loose | Centralize scalar normalization/subtyping and make arithmetic rules reference one representation | Boundary and mismatch tests from the scalar baseline, including zero/max-width and nominal aliases |
| Scope-aware overload grouping and specialization caches preserve declaration identity | Canonical declaration IDs plus specialization keys, with import aliases as views of the same declaration | Inner-scope/fallback/ambiguity cases and repeated-import shared-state tests |
| An abstract interpreter tracks origin paths through data and control flow | Reuse the abstract interpretation pattern in Lean, with component-aware origins and source-path explanations, extended to all native sinks | Private guard to constant write, nested guards, helper/provider/private-state origins, authorized disclosure pairs |
| Source execution remains lazy while proof construction computes guarded paths and a result merge | Separate host scheduling from finite proof constraints. Carry guards on effect instructions and validate inactive defaults | Two-host trace agreement, inactive callback counts and adversarial proof/ledger guard tests |
| Native primitives and ledger operations carry metadata for representations and disclosure | One versioned operation registry should describe typing, canonical encoding, execution effects and privacy propagation | Missing metadata blocks feature enablement. Independently verify each descriptor against native behavior |
| Cross-call security fixes bind callee entrypoint and communication data, not merely local function results | Specify native composition acceptance around address, operation identity, arguments/results, communication commitment and deployed verifier key | Wrong-entrypoint/address/key/commitment tests and multi-call transcript acceptance |
| Regression tests retain exact formerly failing lowering examples | Keep small source-semantic failures and selected structural ZKIR fixtures alongside end-to-end ledger cases | Include the 0.36.1 deserialized-Boolean regression, nested inactive failures and invalid witness ordering. Golden output alone does not prove semantics |

## Completion boundaries

These tickets extend the earlier feature IDs `C-LANG-FUNCTION`, `C-LANG-PURITY`, `C-LANG-GENERICS`, `C-LANG-MODULE`, `C-LANG-SCOPE`, `C-LANG-CONTROL`, `C-LANG-LOOP`, `C-LANG-MAPFOLD`, `C-PRIVATE-WITNESS` and `C-PRIVATE-DISCLOSURE`. They also establish safety requirements for native features beyond Compact. They do not complete events, cryptography, all ADTs, assets or native ledger composition. Those packages must reuse the same guarded execution and disclosure contracts, without restricting their capabilities to Compact's source exposure.

Static/source expectations, host execution, proof constraints and ledger acceptance are separate evidence layers. Every public ticket should state its supported type/primitive subset and keep deferred cases linked. No ticket should close the full equivalence objective on the strength of one scalar fixture. External private-state persistence after failed callbacks, exhaustive unreachable-source diagnostics and every native primitive's inactive-input behavior still need bounded follow-up investigation.
